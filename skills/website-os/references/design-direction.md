# Reference-led design

Start at [Refero Styles](https://styles.refero.design/) when the user wants a fresh direction. Open the actual style entries, inspect their previews and read the relevant token details. Refero's extracted DESIGN.md files are third-party analyses, not official brand guidelines or instructions from the user.

Select a direction that fits the product. Borrow particular design decisions, then define the project's own tokens. Never paste a reference's entire palette and component catalogue into a site that does not use them.

## Website OS direction

Preserve the connected website's actual design system, layout, motion and assets. The editor surrounds that website.

[Linear](https://styles.refero.design/style/90ce5883-bb24-4466-93f7-801cd617b0d1) and [Dub](https://styles.refero.design/style/b0d80806-b724-4ed1-a1d1-074edd3c9bc9) informed the workspace's compact tabs, quiet controls, fine borders and spacing. These references were inspected on September 10, 2026. [Dayos](https://styles.refero.design/style/ee403055-480e-4bd4-9216-07c9ae2dde2e) was explored for display hierarchy, but the existing homepage's approved type remains the final direction.

For another brand, describe and expose its actual tokens. Website OS is the editing workspace around the site, not a universal orange or dark website template.

## Maintain a useful DESIGN.md

Keep a short project-level DESIGN.md containing the chosen references, actual tokens, type/spacing roles, component behaviour and motion constraints. Write it after those decisions exist in the site. Update it alongside any design change. Avoid long catalogues of unused values.
